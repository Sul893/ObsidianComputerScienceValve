## Что это и зачем?

**Inversion of Control (IoC)** 
Для начала надо бы понять как писался код до этого.
Вот есть у нас куча библиотек и собственных компонент. 
По отдельности они конечно же работать не будут, они имеют смысл только если работают вместе в каком-то контексте. Т.е должены существовать "склеивающие" классы. 


![[IoC1.excalidraw]]

(стрелки между компонентами показывают что мы внутри создаем новый экземпляр класса к которому направлена стрелка через new)
```java
class Repository1{
	DBLibrary db = new DBLibrary()
	LocalMemLibrary lm = new LocalMemLibrary()
}
```

P.S: я наверное неудачное выбрал названия классов. Репозитеорий тут не имеет интерейса, воспринимать его стоит только как класс


**Видно проблему?**
При изменении класса Базы Данных, смене технологии хранения в локальной памяти или обраотка нового запроса в Контроллере заставит нас переписывать ВЕСЬ связанный код. Т.е предположим мы изменили что-то в API к базе данных, добавили параметр в конструкторе. И тогда нам надо будет изменить КАЖДЫЙ вызов этого конструктора. 
Т.е увеличится [[GRASP#Low Coupling|связность]] между компонентами, что негативно влияет на отладкку, поддерживаемость и масштабируемость кода.


**Решение**
IoC решает эту проблему делегированием внешнему объекту/коду. Т.е некий сторонний код будет брать на себя отвественность управлением зависимостями.
