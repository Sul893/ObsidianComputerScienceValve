
Описывает структуру классов, объектов и их связи меду собой.

#### Структура
Представляет собой прямоугольник разделенный на 3 части: Имя, Параметры, Методы
![[Pasted image 20260807125446.png|460]]
Если класс - интерфейс, то поверх имени дописывается `<<Interface>>`
Уровень видимости прааметра/метода обозначают через следующие символы:
- `+` обозначает public
- `-` обозначает private
- `#` обозначает protected
- `~` обозначает package local

в методе +Method(in/inout/out p: type): type в качетсве параметра может параметр уточняться in/inout/out 

Есть также 3 уровня спецификации:
- Conceptual Perstective. тут все просто: каждый квадратик - просто имя специфичной для домена сущности.
- Specification Perspective. Имеет стандартную структуру котору описал выше. Это более близкий к коду слой
- Implementation Perspective. Уже уточняется на уровне конкретной технологи или языка программирования.

#### Связи
![[Pasted image 20260807133940.png]]
Есть 6 различных свзей между объектами:
- Assosiaton. Устанавливается если два класса как-либо взаимодейтвуют
- Inheritance. Отражает наследуемость классов
- Realisation. Указывает какие классы реализуют интерфейс
- Dependency. Если класс А в методе принимает на вход класс Б, то строится связь А -> Б
- Aggregation. Класс который не может существовать без хотя-бы одного из составляющих
- Composition. Ниодно состовляющее не может сущестовать без корневого Класса.
