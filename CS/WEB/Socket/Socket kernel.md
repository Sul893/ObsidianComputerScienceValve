# Socket Kernel

**Socket Kernel** — объект внутри ядра ОС, реализующий низкоуровневую работу с сетевым протоколом. Хранит TCP-объект, в который записывает и из которого читает информацию.

## Как это работает

При отправке данных приложение через [[Socket API]] передаёт их в Socket Kernel. Тот добавляет протокольные заголовки, управляет подтверждениями доставки (ACK), контролем перегрузки (congestion control: slow-start, AIMD), переповторами пакетов и сегментацией. Готовый пакет передаётся в сетевую карту.

В обратную сторону: сетевая карта принимает кадр → ядро разбирает заголовки → данные попадают в TCP-объект → приложение читает их через Socket API.

Преобразование работает симметрично в обе стороны:

```
Приложение ──send()──→ Socket Kernel ──→ TCP-объект (+TCP-заголовок)
                                              ──→ IP ──→ Ethernet ──→ Сетевая Карта

Сетевая Карта ──→ Ethernet ──→ IP ──→ TCP-объект (разбор заголовков)
                                        ──→ Socket Kernel ──recv()──→ Приложение
```

## Что хранит

Socket Kernel хранит состояние TCP-соединения:
- send/receive buffers (буферы отправки/приёма)
- sequence/acknowledgment numbers
- окно перегрузки (congestion window)
- таймеры (retransmission, keepalive, TIME_WAIT)

Это и есть реальная "конечная точка" на стороне ядра. [[Socket API]] — лишь интерфейс к ней.

Является низкоуровневой частью [[Socket]], на которую опирается [[Socket API]].

## Наблюдение в OS

```bash
# Все TCP-сокеты в ОС (Socket Kernel + буферы)
ss -tn
# State    Local Address:Port     Peer Address:Port
# ESTAB    192.168.1.5:51324      93.184.216.34:80

# Подробно с буферами
ss -tno
# Отображает размер send-Q, recv-Q, таймеры, состояние keepalive
```
